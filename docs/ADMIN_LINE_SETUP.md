# Admin line setup and time conditions

The admin sidebar now has separate Gateway, DID, Inbound Route, Time Conditions, and Outbound Route screens. The DID list can filter by owner, gateway, and setup state. Opening a DID shows a workspace with overview, inbound and hours, outbound, and settings tabs. The route screens inherit the selected owner when opened from a DID.

An administrator can add a weekly schedule to any tenant-owned inbound route from the DID workspace. Schedule input uses the same `InboundScheduleService` validation and `InboundRoutingService` destination ownership checks as customer setup. Intervals use the configured IANA timezone, closure dates are entered as Jalali and stored in Gregorian format, and the closed action may be a same-tenant extension, enabled team, published IVR, announcement, or disconnect. The Time Conditions list shows scheduled DIDs across tenants. The workspace's date/time preview evaluates the saved schedule; it is not a live call test.

The admin Quick Setup flow creates a per-admin resumable draft. It asks for owner, eligible gateway, new or existing DID, inbound answerer and schedule, explicit outbound extensions, and a final review. Draft edits do not change live routes. Completing the review applies the DID, route, and selected outbound assignments in one database transaction. Existing DID changes are rejected if the DID, inbound route, or outbound assignments changed since the admin selected it. Customer-owned gateways must be approved and enabled; global infrastructure gateways may be selected by an admin. Newly created phone credentials appear once on the resulting DID workspace, which is served with `Cache-Control: private, no-store`.

The migration `2026_09_30_000001_create_admin_line_setups_table` stores draft state and an optional temporary announcement upload path. Run `php artisan migrate --force` as part of application deployment. The wizard uses the existing private `ivr` disk and FFmpeg for closing announcements. Admins can discard a draft; its staged upload is deleted. A future retention job can clean long-abandoned drafts and their staged files.

This change only uses Laravel/database configuration. It makes no changes to FreeSWITCH profiles, gateway files, or Sofia state. Existing XML-CURL directory/dialplan lookups receive schedule changes from the database without a reload or restart. New customer-owned gateways still need the separate gateway XML-CURL activation procedure in `CUSTOMER_LINE_SETUP.md` before live service; an approved gateway in Laravel is not proof of SIP registration. After deployment, test a softphone registration, one inbound call during open and closed hours, and one outbound call through the authorized gateway and caller ID.
